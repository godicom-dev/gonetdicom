# Contributing

Bug reports, conformance corrections and feature PRs are all welcome. This
module is a DICOM network library: what it emits and accepts on the wire is the
product, so the bar is conformance rather than style.

## Before you start

- Open an issue first for anything larger than a fix. Two of the current open
  issues are design conversations, and the handler API is mid-change — a PR that
  guesses the shape will be asked to redo it.
- For a conformance question, cite the clause (PS3.7 Table 9.1-4, PS3.8 Table
  9-10). "pynetdicom does X" is strong evidence, "dcm4che does X" too; either is
  usually enough to settle a disagreement quickly.

## What a PR needs

- `go test ./...` green, `go vet ./...` clean, `gofmt` clean. CI runs these on
  Linux, macOS and Windows, Go 1.26 and 1.27, plus `386`, `fuzz` and
  `golangci-lint`.
- A test that fails without the change. For a wire format, pin the bytes against
  pydicom or dcm4che rather than against this library's own output — a golden
  generated by the code under test only proves the code still does what it did.
- One logical change per PR. A fix and a refactor in the same diff will be split.
- A commit message that says *why*: the bug, the clause, the behaviour that was
  wrong. The diff already says what.
- A `CHANGELOG.md` entry under the unreleased version, in the existing voice
  (what was wrong, what it does now).
- No new dependencies without asking in an issue first. `godicom` is the only
  one, and it is the layer that owns DICOM encoding.

## Layout

| package | owns |
|---|---|
| `pdu` | PDU encoding and decoding, fragmentation |
| `dimse` | DIMSE command sets |
| `ae` | association negotiation, SCP dispatch, handlers |
| `status` | status code tables |
| `dicomweb` | DICOMweb client and the `Store` seam for origin servers |

## Behaviour over API churn

The module is pre-1.0 and has been breaking its API deliberately: `StoreEvent`
replaced the inbound `StoreRequest`, `OnUserIdentity` gained a context, and the
Query/Retrieve sub-operation counts moved into the framework. Each of those was
a case where the old shape could hide the truth from the caller. If a PR needs
to break an API to avoid that, say so in the issue; it is not a reason to
refuse.

## Out of tree by policy

Origin-server persistence and authentication (`dicomweb.Store` implementations),
rendering, and a multi-vendor PACS soak matrix are application or deployment
concerns. Example adapters and documented procedures are welcome; the code lives
outside this module.
